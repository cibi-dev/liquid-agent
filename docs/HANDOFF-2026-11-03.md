## 1. Resumen ejecutivo

La app nativa (Tauri 2 / Rust) **ya arranca y muestra la ventana**. El fallo original
—"abre y se cierra" con `0xC0000142`— **no era del código**: era la **etiqueta de
integridad `Low`** de `C:\Users\admin\Proyectos`, que hacía que todo `.exe` de esa
carpeta se ejecutara en *Low IL* y que el proceso de WebView2 no pudiera escribir su
perfil en `%LOCALAPPDATA%` (*Medium IL*).

La etiqueta ya está corregida a `Medium` en los 28.388 archivos de la carpeta, y la app
se verificó funcionando (ventana + servidor + WebView2 conectado).

## 2. Qué se hizo en esta sesión

### 2.1 Causa raíz: integridad `Low`

Medición de la etiqueta efectiva del proceso según la ubicación del `.exe`:

| Ubicación del `.exe` | Integridad del token | Resultado |
|---|---|---|
| `%LOCALAPPDATA%`, `C:\la-test`, Escritorio, Documentos | `S-1-16-8192` (Medium) | — |
| `C:\Users\admin\Proyectos\...` **antes** | `S-1-16-4096` (**Low**) | WebView2 crashea (`0xC0000142`, `STATUS_BREAKPOINT`) |
| Carpeta con etiqueta `Low` + perfil también `Low` | `S-1-16-4096` (Low) | "Funciona" — síntoma, no solución |
| `C:\Users\admin\Proyectos\...` **después** | `S-1-16-8192` (Medium) | ✅ funciona |

Corrección aplicada:

```powershell
icacls C:\Users\admin\Proyectos /setintegritylevel (OI)(CI)M /T /C
# Successfully processed 28388 files; Failed processing 0 files.
```

Comprobación:

```powershell

# Mandatory Label\Medium Mandatory Level:(OI)(CI)(NW)
```

> Aviso: mover el proyecto a una carpeta con etiqueta `Low` (o crearla con herencia
> `Low`) reproduce el fallo entero. Revisar la etiqueta es el **paso 0** ante cualquier
> síntoma de arranque.

### 2.2 Recompilación con MSVC

El binario anterior estaba compilado con la toolchain **GNU/MinGW** (importaba
`msvcrt.dll` + `WebView2Loader.dll`). Tauri 2 en Windows requiere MSVC.

- Compilado con `stable-x86_64-pc-windows-msvc` y un `PATH` limpio → 3m07s, exit 0.
- La toolchain se fijó con `rustup default stable-x86_64-pc-windows-msvc`.
- El error previo `could not execute rustc` / `indexmap` era **contaminación de `PATH`**
  (Strawberry Perl / MinGW de Git for Windows), no un bug del código.
- Binario anterior conservado como `dist-native\Liquid Agent.exe.gnu.bak`.

### 2.3 Perfil de WebView2

Se eliminaron los perfiles corruptos (`EBWebView`, `EBWebView.locked`, `EBWebView2`) de
`%LOCALAPPDATA%\com.liquidagent.desktop`. La app regenera `EBWebView` limpio.

Dos errores distintos observados, ambos resueltos por la corrección de integridad:

| Error | Significado |
|---|---|
| `0x8000FFFF` "Catastrophic failure" | carpeta de perfil inexistente/vacía y sin permiso de escritura |
| `0x800700AA` "The requested resource is in use." | perfil restaurado/copiado y marcado como en uso |

### 2.4 Fix de `llama-server` (commit `a29bef8`)

Las builds actuales de `llama-server` cambiaron `--flash-attn` de flag booleano a opción
con valor; el flag suelto consumía el `-b` siguiente:

```
error while handling argument "--flash-attn": unknown value for --flash-attn: '-b'
```

Ahora ambos backends de `server/backends.js` pasan `-fa auto`.
